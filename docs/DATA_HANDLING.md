# ข้อมูลของคุณถูกจัดการอย่างไร และพิสูจน์ด้วยตัวเองได้อย่างไร

ระบบนี้มีสองส่วน:
- **node** คือโปรแกรมที่รันในเครื่องของคุณ (เปิดซอร์สทั้งหมดใน repo นี้)
- **central** คือบริการประมวลผลของเรา

เอกสารนี้อธิบายว่ามีอะไรส่งออกจากเครื่องคุณบ้าง เราทำอะไรกับมัน และคุณตรวจสอบเองได้อย่างไร
โดยไม่ต้องเชื่อคำพูดของเรา

## อะไรถูกส่งไป central

node ส่งข้อมูลไปให้ central เฉพาะตอนที่คุณสั่งงาน เช่น ถามแชท อัปโหลดเอกสาร หรือ sync แหล่งข้อมูล

| งาน | สิ่งที่ส่ง |
|---|---|
| แชท | คำถาม, ข้อความตั้งต้นของบอท, ชุดสูตรที่ผูกกับบอท, ไฟล์แนบ (ถ้ามี) |
| อัปโหลดเอกสาร | ไฟล์เอกสารนั้น |
| แหล่งข้อมูลสด | แถวข้อมูลที่ดึงมาจาก API ของคุณ |
| ถอดเสียง | ไฟล์เสียงที่อัด |
| ทุกงาน | API key ของผู้ให้บริการ AI ที่คุณตั้งไว้ และที่อยู่ + key ของ Qdrant |

central ต้องได้รับข้อมูลเหล่านี้ เพราะเป็นตัวประมวลผลและเรียกผู้ให้บริการ AI ให้คุณ

## central ทำอะไรกับข้อมูล

- **ไม่บันทึก**: ข้อมูล, key และไฟล์อยู่ในหน่วยความจำระหว่างประมวลผลคำขอนั้นเท่านั้น แล้วทิ้งทันที
  - ไฟล์ชั่วคราวอยู่บน RAM ไม่ถูกเขียนลงดิสก์
- **ไม่ log เนื้อหา**: log ของ central มีแค่ประเภทคำขอกับรหัสผล เช่น `POST /v1/chat 200`
  - ไม่มีคำถาม คำตอบ ชื่อคอลัมน์ ค่าข้อมูล หรือ key
  - ถ้าข้อความ error มีอะไรที่หน้าตาเหมือน key จะถูกลบออกก่อนบันทึก
- **สิ่งเดียวที่ central เก็บ**: สถานะ license ของคุณ และตัวนับจำนวนคำขอ/token รายวัน (ตัวเลขล้วน)
- **ไม่ใช้ข้อมูลของคุณไปทำอย่างอื่น**: ไม่ขาย ไม่แชร์ ไม่ใช้เทรนโมเดล

## ช่องทางที่ปลอดภัย

- node ยอมคุยกับ central ผ่าน `https://` เท่านั้น ถ้าตั้งที่อยู่เป็น http ที่ออกอินเทอร์เน็ต node จะไม่ยอมส่งข้อมูล
- central ปฏิเสธคำขอที่ยิงตรงเข้ามาโดยไม่ผ่าน HTTPS
- ถ้าต้องการเข้มขึ้น ตั้ง `CENTRAL_CA_FILE` ให้ node ยอมรับเฉพาะใบรับรองที่ระบุ (certificate pinning) กันการปลอมตัวเป็น central

## พิสูจน์ด้วยตัวเอง (ไม่ต้องเชื่อเรา)

หลักฐานด้านล่างทั้งหมดมาจากของที่คุณควบคุมเองหรือจากบุคคลที่สาม ไม่ได้มาจากเรา

1. **อ่านโค้ด node**: การส่งข้อมูลไป central ทั้งหมดอยู่ใน `app.py` (ฟังก์ชัน `central_json`, `_ingest_via_central` และ endpoint แชท/ถอดเสียง)
   - ทีม IT ของคุณตรวจได้ว่าส่งอะไรออกไป และส่งไปที่ไหน
2. **ดูเครือข่ายเอง**: node คุยออกไปแค่ **central** กับ **ผู้ให้บริการ AI ที่คุณเลือก**
   - ตั้ง firewall ให้ออกได้เฉพาะปลายทางเหล่านี้ แล้วตรวจ traffic ได้เลย
3. **key ล่อ** (พิสูจน์ว่า key ไม่ถูกเอาไปใช้ที่อื่น):
   1. สร้าง API key ใหม่ ใช้กับระบบนี้เท่านั้น และตั้งเพดานค่าใช้จ่ายไว้
   2. ดูประวัติการใช้งานของ key นั้นในหน้า console ของผู้ให้บริการ (Google, OpenAI, SiliconFlow ฯลฯ)
   3. ทุกการใช้งานควรตรงกับเวลาที่คุณใช้ระบบจริง ถ้ามีการใช้ในเวลาที่คุณไม่ได้ใช้ จะเห็นทันที
4. **log ของ Qdrant ของคุณเอง**: central ควรเข้ามาอ่านหรือเขียนข้อมูลเฉพาะตอนที่คุณถามหรืออัปโหลดเท่านั้น

## สิ่งที่พิสูจน์ด้วยวิธีข้างบนไม่ได้ (บอกตรง ๆ)

วิธีข้างบนพิสูจน์ "พฤติกรรม" ได้ เช่น ไม่มีการแอบใช้ key และไม่มีการแอบเข้าถึงข้อมูลนอกเวลาที่คุณใช้
แต่ในทางเทคนิค ไม่มีวิธีใดพิสูจน์ได้ 100% ว่าเครื่องปลายทางไม่ได้คัดลอกข้อมูลไว้ระหว่างประมวลผล
ส่วนนี้คุ้มครองด้วยข้อตกลงการประมวลผลข้อมูลระหว่างเรากับคุณ

## แนะนำเพื่อลดความเสี่ยงฝั่งคุณ

- **ใช้ API key แยกเฉพาะระบบนี้** และตั้งเพดานค่าใช้จ่ายรายเดือน ถ้ามีปัญหาก็ลบ key ทิ้งได้ทันที ความเสียหายไม่เกินเพดาน
- **ตั้ง Qdrant ให้มี API key เสมอ** และเปิดผ่าน HTTPS
- **อย่าแชร์ไฟล์ `.env` หรือโฟลเดอร์ `data/`** ไฟล์เหล่านี้มี key และ license ของคุณ
